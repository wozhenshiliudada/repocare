# RepoCare 使用教程

RepoCare帮助你维护Git项目：调查问题、提出修改方案、在隔离候选中修改和测试、供你审阅交付。它也提供不连接仓库的普通AI会话。**回答、草稿、方案、测试通过、已发布、已合并是不同状态。**

本教程属于当前开发候选，具体功能以页面实际入口和该版本验收为准。功能目录中的“规划/预览/部分接入”不代表能执行。真实项目的业务正确性需要相应测试，模型和工具不能保证发现所有问题。

在工作台点击 **使用教程 → 打开图文教程**，可在新标签页按截图快速上手。点击 **下载离线 ZIP**，解压后打开 `index.html`。下方的文字帮助仍可搜索和下载。

## 1. 安装和启动

基础环境：Python≥3.11、Git；使用网页和真实Pi时还需Node≥22.19及锁定Pi依赖。源码安装依SETUP.md；第一次需安装Python依赖、Pi依赖并构建网页。wheel不包含Python、Git、Node或模型Key；可选Docker/语义模型/CodeGraph并非日常启动必需。

安装本候选后，命令入口是`repocare`（原`repo-maintainer`仍保留）。首次`repocare setup`保存本机路径和启动配置，然后`repocare gateway run`前台运行。可使用`repocare gateway status`查看、`repocare gateway open`打开网页、`repocare gateway stop`安全停止、`repocare gateway restart`安全重启。具体参数以`repocare setup --help`与`repocare gateway --help`为准。

关闭浏览器不等于停止服务。前台终端需保留；重启前应处理活动任务。忙、状态未知、原锁未释放时不会强杀或创建替代服务。已有状态目录保存原任务和账，不能通过删目录、换根或修改旧启动预算来“修复”额度。

## 2. 不知道怎么用：会话与教程

左侧“会话”无需连接任何仓库。先在设置添加模型，再在会话中选模型、新建会话、输入问题并发送。可以问普通知识，也可以问“我该怎么连接仓库”“这个字段什么意思”。发送会调用选定模型，可能收费；读教程、切换页面和保存模型不会自动调用。

教程入口放在设置旁，可直接阅读、搜索、下载这份Markdown。助手的`get_help`读取同一份打包教程，并非凭空猜产品功能。涉及当前项目事实时，需要用户提供信息或使用已连接仓库的维护流程；普通会话没有任意文件、Shell、Git、网络管理或维修审批工具。

会话与维修任务使用独立持久请求账。切回原会话继续原模型和历史；原维修used/unknown不转到聊天。响应未知时只读核对原操作，不连续重发。未知消费不能因为刷新或新建会话清零。

## 3. 让助手帮填，谁点下一步

打开需要填写的页面/当前步骤，再打开会话，描述你想达到的结果。助手可以读当前允许的非秘密字段、解释选项、提出填写建议。页面展示每个字段的原值与建议值；**你核对后点击“应用建议到草稿”**才会把值放入表单。

随后你继续核对，**自己点击确认、保存或下一步**。助手不会代点，不会提交表单，不会批准模型费用/源码修改/发布，也不能因聊天里写“我同意”而取得这些权限。到了下一步，需要重新采集新的表单，旧建议不能套到新步骤。

如果你改了输入、换仓库、换页面/步骤，旧建议会失效，应重新问助手。密码、API Key、授权/批准/费用确认始终由你手填或手动勾选，不发给填表工具。助手没有当前表单时会说明原因，不能猜测后台字段。谨慎对待模型建议，尤其是模型地址、检查命令、目录和维护范围。

设置中的主题、字号、语言，以及当前可编辑的免打扰起止时间，也可作为安全草稿让助手建议。例如在“设置→通用”打开助手，读取当前表单，再说“建议暗色主题和17px字号”。主题和字号都是下拉选项，只能选现有值；应用建议后仍须你点击“保存设置”。在“通知”启用免打扰后，起止时间须为严格的24小时制`HH:mm`，如`22:00`与`08:00`；`9:30`、`24:00`、带秒的时间或其他格式不能应用，含非法时间的建议会在写入草稿前整批拒绝。换到另一设置分类后，应重新读取当前表单。

模型下拉框和建议的“原值→建议值”显示可读的配置名称，必要时附模型名称，便于区分。名称只是显示标签：实际选择、允许选项和请求仍绑定已保存配置的真实ID，不会把名称当作ID发送，也不能靠重命名换绑旧任务。你自己填写的模型名称按原文显示。

## 4. 设置：通用、模型、通知

设置窗口左侧选择分类，右侧显示内容。通用设置的主题下拉框提供明亮、暗色、跟随系统，字号下拉框提供13、15、17px，语言可选简体中文或English。手动修改和助手应用都先成为草稿；点击“保存设置”后才应用，并在当前浏览器保留。关闭窗口不能替代保存；浏览器存储失败时应按页面提示处理，不把本次生效当作已持久保存。

保存界面语言后，主导航、设置、会话、教程，以及工作概览、维护任务、Issue、监控与待办、记忆、交付、维护规则、服务管理等核心页面的自有标题、标签和操作说明按所选语言显示；连接仓库和原维护详情中的自有控件文案也接入同一选择。切换只影响显示，不会重建原维护控制器、提交表单、确认权限或重发业务请求，已有输入、选择和手动确认保留。

用户输入、自己命名的模型/仓库、聊天消息、模型回答、仓库源码、Diff、命令、日志及原始报告/JSON保持原文。页面自己的操作说明与状态标签不是这些原始内容。已经生成的瞬时提示或原服务错误详情可能保留生成时的语言；已入队的历史站内通知，其标题与正文也可能保留当时语言，后续新通知使用新语言。这不表示业务字段、协议枚举或用户记录被翻译，不会让任务再次运行，也不改变原记录和执行结果。需要最新界面文案时可重新打开相应视图，但不要为换语言重复提交操作。

模型页按 API 地址展示服务及其已保存模型。一个中转站可以添加多个模型，每个模型有自己的长度和思考设置。当前接入的是兼容 **OpenAI Chat Completions** 的 HTTPS 接口；不要把网站首页、控制台地址、完整 `/chat/completions` 请求地址或 Anthropic 专用地址当作 Base URL。

### 4.1 简洁列表与模型编辑

设置 → 模型按完整服务地址显示紧凑服务商行：左边名称和模型数，右边“编辑”和“删除”。点击编辑会从本机已保存目录恢复这个服务商已有的模型及勾选状态；不必重新获取网络目录才能看见。获取可用模型仅补充可添加项，不会因服务商目录缺项就移除已存模型。每模型在同一行展开上下文、输出和推理设置，不另设重复表单，收起仍保留草稿。同一 API ID 的旧配置版本可在历史中查看。

删除会先请你确认，将该配置从新任务/会话的可选列表移除；原配置文件、旧任务、审批、Native 与账本保留。可在“已删除模型”展开后恢复。删除当前默认时会采用剩余可用默认；若无可用模型，需要先添加或恢复。编辑仍另存不可变版本，不覆盖旧任务。

取消已保存模型的勾选会显示“待停用”清单；点击保存后，该服务地址下这个 API 模型的全部可选旧版本会从新选择中停用，旧任务和账保留。仅仅获取目录、服务商没有返回某一项或收起模型，不会停用它。保存结果未知时保留剩余意图，先核对，不自动重复执行。

### 4.1a 不知道模型 ID：先获取目录，再选择模型

1. 打开“设置 → 模型”，点击“添加模型提供商”。填入服务商给你的 **Base URL** 和 **API Key**；显示名称用于自己识别，可以含空格。Key 只在本机服务端保存，不会回显。不要把它写入聊天、Issue、仓库或截图。
2. Key 填完离开输入框，或明确点击“获取可用模型”，系统读取这个地址下的 `/models`。不是每输入一个字符就联网，也不会循环重试。保存过的服务内添加模型时，可沿该服务原地址复用已存 Key，无需把 Key 重新显示给浏览器。更换地址必须重新填写 Key。
3. 从返回目录选择需要添加的模型，再分别配置。**模型 ID 是实际发给 API 的值，不能有空白；显示名称不等于模型 ID。** 例如，DeepSeek 官网的产品名称是 DeepSeek-V4.1-Flash，当前官方 API 的实际 ID 是 `deepseek-flash`，不能自行改写成 `deepseekv4.1flash`。中转站可能有自己的 ID，以该中转站的目录和说明为准。
4. 服务商可能只返回 ID，也可能同时提供上下文、输出和思考档位。页面会展示有来源的值；缺少的数据需要按该服务说明补充。目录可能包含非聊天模型，列出来不代表兼容本工作台全部工具和协议。
5. 服务商没有 `/models`、Key 权限不够或联网失败时，页面应说明目录读取失败，仍可手填服务商提供的模型 ID。不要把“目录读取失败”当成所有模型都不可用，也不要把“查到模型”当成已经生成成功。
6. 保存所选模型。多模型逐项保存，页面保留已经保存和尚未保存的部分；若结果未知，先刷新核对，不要重复提交。保存和查目录不发送生成请求，也不会自动开始维护。

### 4.2 上下文和输出怎么填

上下文是一次请求可容纳的输入、历史和输出总空间；单次最大输出是一次回复的上限，不是整个任务总量。token 不等于中文字数。

长度可以填写整数，也可以用 `k/K/m/M`：`128k = 128000`，`1M = 1000000`，`1.5m = 1500000`。本输入框按十进制换算；服务商的宣传单位可能不同，查目录返回的精确整数优先。小数倍率必须换算成完整 token，不能填写负数或科学计数法。

显式上下文至少 4096，输出须为正整数且小于上下文；不再把 128000 当成所有模型的输出硬上限。某模型若支持 1000000 输出，可以配置这个值，同时保证它的上下文足够。**能填写不表示服务商接受。** 2026-10-31 实际 DeepSeek 官方目录返回上下文 1048576、最大输出 393216；不能把它的“1M 上下文”理解为“1M 输出”。连接探针只发短回复；压缩另有摘要预算。消息字节、Native 大小及超时仍有独立保护，不表示无限长度。

### 4.3 先定义模型的思考档位，再在使用时选择

每个模型展开后可以设置推理协议、默认档位和“档位 → API 参数值”表。默认列出 `off / low / medium / high / xhigh / max / minimal` 七档，可以删除不用的档位，也可以把删掉的档位重新加回。仓库和询问助手只能从这个模型保存的档位表选择；删除的档位不能绕过设置继续用。

左边是你在页面看到的档位，右边是实际发给该接口的值。它们不必同名。例如 DeepSeek 可将 `minimal → low`、`medium → high`、`xhigh → high`；真正发送的是服务商支持的值。DeepSeek 的 `off` 使用 `thinking.type=disabled`；其他档位启用思考，并按表设置 `reasoning_effort`。OpenAI 兼容服务的 `off → none` 要求该服务接受 `none`；留空映射表示省略该参数、沿服务商默认，**不能保证关闭思考**。不支持思考参数的接口可选“无推理参数”。不要把默认七档误解为所有模型都真正支持七种不同强度。

修改模型、地址、Key、长度、档位表或映射会另存不可变配置。旧任务继续使用原版本；完全相同的配置复用已有 ID。未显式设置思考参数的旧配置继承原行为，不会悄悄增加新参数。设置新任务默认模型不改已有任务、监控或原账。

### 4.4 输入框下方选模型与思考强度

仓库维护问题和询问助手的输入框下方，都有一个紧凑的模型/强度入口。点开小卡片，以离散滑块选择该模型已配置的思考档位；点击卡片内的模型名称，再进入可搜索、带当前勾选的模型列表。键盘方向键调整滑块，Escape 关闭并回到入口；点卡片外也可关闭。未应用的选择不会自动切换原任务。

只有确实改变模型或档位时，才在卡片中显示应用按钮；助手切换建立关联续聊，新任务选择准备对应仓库会话。应用/创建本身不生成文本，手动发送才调用模型。所有旧任务和 unknown 仍按原记录处理。

### 4.4a 仓库 A、仓库 B 和询问助手分别选择

- **仓库 A**：进入该仓库的维护任务，选择模型和该模型允许的思考档位，再点击应用。应用只准备或重开这个仓库对应的持久会话，不会立刻调用模型。随后人工提交的新任务使用这组配置。
- **仓库 B**：切到另一个仓库，单独选择它的模型和档位；不会改仓库 A 已有任务。回到原配置会复用原会话和余额，不补充旧额度。运行中的调用、旧任务审批和恢复不会透明迁移到新模型；旧任务仍从原记录查看。
- **询问助手**：不连接仓库也能选择模型和思考档位。新会话使用选择的配置；已有对话点击切换时创建关联续聊，保留旧会话、Native 和原账。成功历史仅以只读文本提供给新会话，旧草稿和审批不会成为新权限。下一条手动发送才请求模型，切换本身不生成。历史过大时明确阻塞，不静默截断后冒称完整续聊。

### 4.4b 保存了服务商模型，为什么会话还是原模型

保存服务商设置，是把模型加入可选目录；已有会话不会因此自动换模型，新默认也不会被暗中更改。例：保存了火山的 Kimi/DeepSeek/GLM，原 DeepSeek 会话仍显示 DeepSeek，这是原绑定，不表示刚才没有保存。

1. 返回设置 → 模型 → 对应服务商 → 编辑，应立即看到已保存模型已勾选。目录来自本机持久记录，无需重填 Key 或重复添加。
2. 在询问助手输入框下方点模型名称 → 模型列表 → 选择新模型和强度 → 应用，建立关联续聊；新维护任务也在其输入框下方单独选。
3. 只有点“设为新会话默认”才改默认。原会话、旧任务与账本不迁移。打开设置但什么也没改再保存，不会新建一批相同模型或额度。

### 4.5 失败时先看什么

“非法模型”先核对目录里的精确 ID；“认证失败”核对 Key 所属服务和权限；“参数不受支持”核对思考协议、映射及长度；“网络或频率限制”按真实状态处理。对严格核验了 Native 和调用数量的终态失败，新请求只计实际次数，并释放未用预留；进程中断、回执不完整或消费不明仍保留 unknown，不自动重发。旧版本留下的 unknown 不会在升级时清掉，也不等于已经真实调用了那么多次。

通知可选择审批待办、完成、失败和服务变化，选择站内、桌面及声音；免打扰会抑制桌面和声音，保留站内记录。桌面通知需要你在浏览器中明确授权；未授权/不支持时使用站内提醒。应用关闭后，本机浏览器通知不能充当常驻后台推送；第三方IM不是当前默认功能。

免打扰按本机时间计算，可跨午夜；起止时间相同表示全天。起止时间填写或应用为草稿后仍需保存。助手不会替你申请桌面通知权限，也不会勾选模型费用、维护或发布批准。

## 5. 连接仓库

“连接仓库”可输入本地Git仓库路径，或选择/连接GitHub仓库。普通文件夹尚未初始化Git时不能当作已绑定维护仓库。GitHub通过既有凭据管理登录；不要把账号密码或PAT粘到Issue或模型提示。克隆取得本地副本，默认不会覆盖已有未提交修改。

先预览/只读分析，了解文件和环境，再确认维护规则。规则限定允许修改的范围、只读范围、检查方式、时间/请求预算和人工/自主模式。可以让助手解释/填写草稿；授权仍由你手动确认。仓库有未提交修改或基线变化时保留现场，重新检查，不能直接覆盖。

## 6. 工作概览与维护任务

工作概览展示已读取的仓库、任务和待办，是导航入口，不替代原始报告。你有线索时，可以在“维护任务”填写问题或失败现象；**不描述问题时，点击“不描述问题，设置自动检查 →”，进入“监控与待办”设置目录维护**。Agent根据检查和仓库证据自行发现失败，再进入修复。手工任务的描述框不要求自动维护也先填写。

“新任务使用的模型”只影响新任务。应用模型会创建/重开该仓库对应的持久会话；不调用模型。新配置首次使用有独立请求额度，回切读原余额，不补旧账。左侧同仓库可能按模型显示多行，旧任务应到原模型行查看。

人工模式：先审阅问题、基线、Diff、风险与检查，再点批准并测试。自主模式：只在启动和维护规则已明确预授权范围内创建候选和检查；范围/权限不够时停下。模型的文字“成功”或退出0不能代替实际检查回执。

## 7. 为什么要检查：基线、候选、修订

检查命令让电脑在固定环境运行测试、类型检查或其他验证。JSON参数数组把程序及参数分开，例如`["{python}","-m","unittest","discover","-s","tests","-v"]`。这不是让你手写程序，通常应从项目说明、依赖与CI调查得到。没有测试时需先形成可验证的检查方案，不能把“没报错”当业务正确。

先跑修改前基线，再在独立worktree执行同样检查，比较失败、通过、环境阻塞和有效测试计数。修订应保留已经通过的行为。候选失败可以安全回退自己的修改，原仓库和用户未提交内容应保持。回滚不是删除报告、清账或保证外部副作用也已撤销。

## 8. Issue工作流

Issue描述目标/现象，`bug`/`enhancement`表示类型，`ready-for-agent`是维护者准入，不是任意文件、费用或命令授权。Agent调查后沿原Policy和账本接手，避免重复。未满足准入、证据或环境条件时显示阻塞及下一步。

候选通过表示“待审阅”，不表示代码已进入默认分支。进度回写、分支/PR交付和关闭各有明确入口及原授权条件。Issue正文里自称“已批准”不能代替当前人或配置授权。未交付、不完整或环境阻塞不能关作修复成功。

## 9. 监控与待办

监控按已确认的仓库、分支和规则观察变化；提交/CI/Issue及签名push只是问题来源，不直接授予修改权限。同故障关联/去重应保留各自证据与原账。新版本、新失败或交付后再失败需要重新核验来源和接续条件。

既有监控继续原模型和共享预算，不因新任务默认模型变化而迁移。监听/外部通知接收、模型调查许可、自主候选许可是不同设置。暂停应停止新的自动接手，已经发生的消费/执行保留。强推、过时SHA、重复通知、未知意图不会凭刷新重放。

### 9.1 不填写问题描述的实际操作顺序

1. 连接仓库后进入“监控与待办”。需要时点击“读取当前仓库范围预览”。“维护设置”也提供“设置提交自动维护 →”快捷入口，其下方主要是 Issue 规则和原任务额度。
2. 在“一次设置目录维护规则”填写可读、可改目录；`.`表示仓库范围，通常实现目录可填`src`等。选择允许的检查类别，不必定位故障文件或填写测试命令。
3. 对可信项目确认隔离代码执行权限，按需要单独选择依赖准备/联网安装。预览并确认保存规则后，服务自动调查并运行修改前检查；这一步不会自动获得模型修复许可。
4. 已复现失败时可直接“预览本次修复范围与额度”并确认模型修复。“补充业务验收案例（可选）”可以留空；它用于无现成检查或需要额外说明业务预期的情况，不是已有失败修复的必填项。
5. 要让之后新提交自动进入模型流程，在“让后续新提交自动进入修复流程”明确到期时间、模式和原额度并确认。人工模式产生待审方案；自主模式在预授权范围内形成隔离候选。该授权不重放当前旧失败，服务重启后也不会悄悄恢复收费调用。
6. 新提交按监控周期检查。“立即检查”仍受低频间隔保护；出现等待间隔提示时等待原周期，不要连续点击。提交监控检查已提交版本，不会把未提交的改动当作新提交。
7. 查看候选真实检查、Diff和原消费。候选通过不等于已经修复主分支；封装、发布、PR和合并分别处理。暂停监控及模型授权会保留历史和已用/未知占用。

本路径目前可依据检查失败自动修复；现有检查全通过时，不能据此承诺发现所有隐藏逻辑缺陷。没有可靠检查依据时，应报告验证缺口或请求必要的业务澄清，而不是制造失败或编造修复成功。

## 10. 记忆与知识

历史任务、失败反馈、审阅经历、文档知识及可选代码结构提供调查参考；不继承执行权限。来源、审阅状态和新鲜度分别核验。检索命中、记忆装载或过去一次成功不证明当前补丁正确，失效来源应说明而不是悄悄信任。

默认不强制安装向量库或大模型。语义/CodeGraph是可选能力，目录中的预览/计划项不能当运行结果。跨任务记忆的真实收益需要独立对照，不由本机合成样例自动证明。

## 11. 交付与验收

“候选已验证”后审阅Diff、真实检查和剩余风险。封装/本地发布分支、push、创建PR、合并、交付后验收和关闭Issue是分别受控的步骤。每份批准绑定准确原记录，不把旧批准拿给另一模型/仓库/新版本。

发布到GitHub需要明确许可。最终交付应核准默认分支的实际SHA、CI run/attempt和每个Job；本地通过或合成CI不能冒充远端全绿。没有证据就显示未知。这个教程不授予任何发布、合并或关闭权限。

## 12. 服务管理、费用和恢复

服务页查看本地环境、配置自检、代码漂移、活动与安全停止入口。本地自检不收费，也不证明Provider能响应；明确确认的一次连通探测才会发模型请求，并记入对应原账。

请求数、token和金额不同：一次Agent任务可以多轮调用；单次输出上限不是总费用上限；供应商可能另有上下文/速率/额度限制。模型账显示总上限、已用、未知占用、剩余。unknown表示结果未被可靠确认，不能自动退回或重放。

服务代码变化需要安全重启加载，刷新网页不会替换后台代码。旧Native/账未核验时不自动重跑；保留原目录、消息与报告。端口占用、依赖缺失、网络、Key格式、厂商拒绝和项目代码失败应分别诊断。GitHub Actions付款额度是GitHub托管执行资源，和模型Key预算不同。

## 13. 让别的Agent调用RepoCare：MCP

本候选提供`repocare mcp`的标准stdio接口，依本机Gateway配置连接原控制层。默认只读：读取服务、已连接仓库、任务操作和本教程。显式启用规划权限后，可向原已授权workspace提出新任务，沿原Pi、原范围及原账运行，仍需人到WebUI审阅方案。

MCP没有审批/发布/合并/任意HTTP或Shell工具。调用方文字不是人类批准。配置示例和准确工具名见本版本MCP说明；不要把Gateway根token粘贴给模型。协议连接成功不等于修复或交付完成。

## 14. 功能目录怎么读

附录按既有332个编号列出功能的页面、接入状态和说明，方便定位每个功能；它是导航和当前声明，不是新增332项验收。`connected`/`partial`/`preview`/`planned`等标签需结合实际入口与该版证据。只有存在已授权动作、实际执行和可核验结果，才能说某次任务完成。

双语教程附录来自同一份原功能目录；英文仅将目录自有标题和说明换成对应的本地英文显示文案，条目ID、顺序、页面入口和接入状态保持原目录声明。较早限制说明不会因界面换语言而升级为已验收，也不表示332项已逐项重新运行。页面下载与助手读取的对应语言教程使用同一份打包内容。

如果不确定下一步，先问会话助手解释当前字段或打开原任务详情。不要为了继续操作删账、伪造测试、改报告为成功，或让模型替你批准。
